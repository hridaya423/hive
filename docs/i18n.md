# Interface text and languages

All text that a user reads comes from the catalogs in `packages/i18n` (`@openbot/i18n`). Desktop,
shared UI, the web client and mobile use the same catalogs. Hive ships English only (`en`). The
catalog structure stays, so a language can come back from the `upstream` remote.

## Where the text lives

`packages/i18n/src/messages/<locale>/<area>.ts` holds one area. The area is the surface where a
reader looks for the text: `settings`, `chat`, `mobile/settings`, `error/team`.

- `common` holds short words with no context of their own: Cancel, Save, Retry. If the
  translation can change with the screen, put the key in that screen's area, also when the English
  is the same.
- `format` holds units and list words that `createFormat` uses.
- `language` holds language names, such as the dictation languages.
- `error/*` and `status/*` hold English that the main process, the backend, a host or the team
  client sends. See [Text from another process](#text-from-another-process).
- `mobile/*` holds text that only the mobile app shows. The mobile bundle contains `common`,
  `format`, `language`, `error/*`, `status/*` and `mobile/*`, and no desktop areas.

`en/index.ts`, `en/mobile.ts`, `en/source.ts` and `en/shared.ts` only join the area modules. Do not
put keys in them.

## Add a key

1. Add the key to the English module of its area:

   ```ts
   export const messages = defineMessages("settings", {
     "settings.language.title": "Language",
     "settings.agents.count": { one: "{count} agent", other: "{count} agents" },
   });
   ```

   `defineMessages` makes the build fail when a key does not start with the module prefix. A
   message with `{count}` has plural forms. Other values are `{name}` placeholders.
2. Render it. Write the key as a literal, so `bun run i18n:check` and a search can find it.
3. Keep the label of a button, tab, menu item or badge short. A button does not wrap or shrink, so a
   long label pushes the row; a badge or menu item can cut the label off. Find the shortest natural
   word.

For a map from a value to text, map to keys, not to text:

```ts
const STATUS_LABEL = {
  running: "agent.status.running",
  stopped: "agent.status.stopped",
} as const satisfies Record<AgentStatus, AppTextKey>;
```

## Use the text

| Surface | API |
| --- | --- |
| Desktop renderer and `packages/ui` | `const { t, format, errorMessage } = useText()` from `@openbot/ui/text` |
| Mobile screens | `useText()` from `@/shared/lib/text` |
| Mobile code outside React (stores, `Alert.alert` callbacks) | `currentText()` from `@/shared/lib/text` |
| Main process, native UI (dialogs, menus, window titles) | `language.translate` from `LanguageService` |
| Main process, backend, team client: errors and status text | `sourceText(key, params)` from `@openbot/i18n/source` |

- In `packages/ui`, call `useText()`. Do not add a `t` prop. The text context is the one
  application value that shared UI reads from a context. Outside a provider it is English, so a
  test or a story works without setup.
- `errorMessage(error, fallback)` is `userErrorMessage` in the reader's language. Give it a
  translated fallback: `errorMessage(err, t("skill.saveFailed"))`.
- The renderer's `I18nProvider` supplies the text context in every window. The web client and
  Storybook use `StaticI18nProvider` with a fixed locale.

## Text from another process

An error crosses IPC as its message only, and the Team API sends `{ error: message }` to clients of
every released version. So the sender writes English, and the screen translates it:

```ts
// main, backend, team client
throw new Error(sourceText("error.skill.nameTaken", { name }));
```

The English text of a source key must be the same, byte for byte, as the text the code sent before.
Old clients and code that compares error text depend on it. To change the English of an
`error.*` or `status.*` key, treat it as a wire change: find every comparison and every older
client that reads it.

The screen calls `errorMessage` or `sourceText(text)`. These find the key whose English template
matches the text and render the key in the reader's language. `{count}` matches a number, and the
other placeholders match any text. `{reason}` and `{detail}` are translated again. Text that no
template matches, such as text from an older host or a provider, shows as it is. A remote client
reads its own language, not the host's.

`bun run i18n:check` fails when two source templates can match the same text.

## Do not translate

- Protocol values, IPC channels, identifiers and saved values. Map a saved value to a key when it
  renders; never save translated text.
- Analytics event names and properties, and log lines.
- Agent prompts and the text that the app sends to a provider.
- User content: messages, file names, agent names.
- Product and brand names: OpenBot, provider names, ZIP, JSON.
- Errors that only a malformed payload, a programming error or a development tool can cause, such as
  a failed shape check in an `*-inputs.ts` file.

## Numbers, dates and sizes

Do not call `toLocaleString()` without a locale, or with a fixed `"en-US"`: both ignore the
language that the user selected. Use `format` from `useText()`:

| Method | Output |
| --- | --- |
| `format.number(value, options)` | 1,234.5 |
| `format.compact(value)` | 1.2K |
| `format.percent(ratio)` | 25% for 0.25 |
| `format.currencyUsd(value)` | $1.50 |
| `format.date(value, options)` | `Intl.DateTimeFormat` options |
| `format.list(items)` | a, b, and c |
| `format.fileSize(bytes)` | 512 B, 12 KB, 3.4 MB |

The mobile app runs on Hermes, which may not have `Intl.PluralRules`, `Intl.ListFormat` or compact
numbers (not confirmed on a device). `packages/i18n` has a fallback for each one.

## Checks

- `tools/ui-foundation/no-hardcoded-ui-text.grit` fails on literal text in `src/renderer/src`,
  `packages/ui/src` and `apps/mobile/src`: JSX text, a literal `aria-label`, `title`,
  `placeholder`, `alt`, `label`, `description`, `accessibilityLabel` or `accessibilityHint`, a
  literal toast or alert, and a literal `errorMessage` fallback. Tests and stories are not checked.
- `bun run i18n:check` fails on a key with the wrong prefix, a key in two modules, a translated key
  that English does not have, a placeholder that English does not have, a plural shape that is not
  the same as English, an ambiguous source template, and an English key that no code names.
  `bun run i18n:check --json` writes `.openbot-build/i18n-report.json`.

## Bring a language back

1. Restore `packages/i18n/src/messages/<tag>/` from the `upstream` remote.
2. Add the tag to `APP_LANGUAGES` in `packages/contracts/src/app-language.ts` and to
   `TRANSLATED_LOCALES` in `packages/i18n/src/locale.ts`.
3. Add the catalog to the `catalogs` maps in `app-catalogs.ts`, `source-catalogs.ts`,
   `format-catalogs.ts` and `mobile-catalogs.ts`, add its name to `languages.ts`, and add its plural
   rule to `BUILT_IN_RULES` in `plural.ts`.
4. Run `bun run typecheck:i18n` and `bun run i18n:check`.
