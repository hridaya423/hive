## Phase 9 (branch `phase/9`, 2026-11-03)

### Task 9.1: spike on the mini, no account linked
Scratch folder `~/honey/hive-phase-9-spike` on the mini (`spike.mjs`, `link.mjs`, `qr/`). Not in git.
- **Version and license.** `bun add --exact baileys@7.0.0-rc14` (npm `latest`; `legacy` is 6.7.24). Baileys is MIT. It requires `libsignal@6.0.0`, which is **GPL-3.0** (`node_modules/libsignal/package.json`, full GPL text in its `LICENSE`). Baileys imports it directly (`lib/Utils/crypto.js`, `lib/Signal/libsignal.js`). Version 6.7.24 requires a git copy of the same GPL library. No other dependency of Baileys is copyleft (`whatsapp-rust-bridge` MIT, `ws` MIT, `protobufjs` and `@hapi/boom` BSD-3, `lru-cache` BlueOak, others MIT). The repo has no GPL-3 dependency today (a scan of `node_modules` found only LGPL `@img/sharp-libvips` and dual-licensed `node-forge`).
- **Decision taken, change only on Hridya's word.** AGENTS.md makes PolyForm Noncommercial 1.0.0 non-negotiable and forbids incompatible dependencies. GPL-3.0 code in the same program cannot be conveyed under PolyForm. So `baileys` is NOT in `package.json` or `bun.lock`. The adapter is typed against a small socket interface (`whatsapp-socket.ts`), and `whatsapp-baileys.ts` loads Baileys at run time from a separate install (`<userData>/whatsapp/runtime`, made by `bun scripts/install-whatsapp-runtime.ts <folder>`, version pinned exactly in `BAILEYS_VERSION`). This keeps the repository free of GPL code. It does not settle whether a Hive build that has this install is itself a combined work. GPL duties start only when someone conveys the program, and Hive is private, so this is low risk for personal use. To accept the GPL instead: `bun add --exact baileys@7.0.0-rc14` and change the loader to a normal import. Alternative with a clean separation: run Baileys as a child process over stdio.
- **Runtime.** Baileys loads and opens a socket under **Bun 1.4.2** and under Node 25.6.0 on the mini. Both reached the WhatsApp servers, got the latest web version `[2,3000,1043857760]` and emitted a `qr` event (277 characters). Baileys is ESM (`"type": "module"`), engines `node >=20`. Bun blocked two install scripts (`baileys` preinstall: a Node version check; `protobufjs` postinstall). Both are harmless to skip.
- **Auth state.** `useMultiFileAuthState(folder)` writes JSON files in that folder: `creds.json`, `app-state-sync-key-<id>.json`, `session-<address>.json`, `pre-key-<n>.json`, `sender-key-*.json` (`/` becomes `__` and `:` becomes `-` in names). It creates the folder if it is missing. Nothing is written until the first `creds.update`, so an unscanned spike leaves the folder empty. Hive uses `<userData>/whatsapp/auth` (`src/main/application-services.ts`). The Baileys README says this store is not for heavy production use; one file per key is fine for one account.
- **QR.** `connection.update` carries `qr`. A code works only while its socket stays open, so a saved PNG expires at once. `link.mjs` keeps the socket open, rewrites the PNG on each code and opens it. I did not run `link.mjs` and did not scan anything. Spike QR images exist (valid PNG, looked at it) only to show the step works.
- **Message types the API exposes** (`Types/Message.d.ts`, `AnyMessageContent`): text (with mentions, link preview, quoted reply, `edit` of an own message), image, video (with `ptv` video notes, GIF), audio (`ptt: true` voice note), sticker, document, location, contacts, poll, event, album, reaction (`react`), pin, forward, delete, group invite, button and list replies, product. Media: `downloadMediaMessage(message, "buffer"|"stream", ...)`.
- **Reconnect API.** `connection.update` with `connection: "close"` and `lastDisconnect.error.output.statusCode`: `DisconnectReason` is `loggedOut` 401, `connectionReplaced` 440, `connectionLost`/`timedOut` 408, `connectionClosed` 428, `badSession` 500, `restartRequired` 515, `forbidden` 403, `unavailableService` 503.
